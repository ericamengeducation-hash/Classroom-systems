The system

One unit, five moves, two tools I built

Students study a historical mystery, pick a theory, and have to convince the room. The two tools below sit at opposite ends of that arc: one teaches the skill, the other turns the whole class into the audience that judges it — and then sorts them into the exact revision group each writer needs.

Move 1Teach the skillClaim, evidence, counterargument — on demand, not as a lecture.
Move 2Build the caseEach student argues one theory from real evidence.
Move 3Blind class votePapers read with no names. The room votes on the argument alone.
Move 4Named feedback groupsSix groups, each with one fix and a line of their own writing that works.
Move 5ReviseBack to the skill pages for the one thing their group is fixing.

Shaded moves are the two tools demonstrated on this page. Everything is built as a single self-contained HTML file — no logins, no student accounts, runs on a classroom projector, a Chromebook or a phone.

Tool 1 · Move 1 and Move 5

The Convincing Desk

Student reference hub

A sixteen-page reference students open while they write. Each page covers one move and opens with a single instruction, so a stuck writer gets one thing to do rather than a wall of advice.

The problem

Mini-lessons land on Monday. The writing happens Thursday. By then the anchor chart is gone and the help is generic.

What I built

One page per move, mapped exactly onto the boxes of the paper organizer, so "go to your supporting detail box" and "go to that page" are the same instruction.

What it changed

Feedback got shorter. Instead of re-teaching, I name a page. The writer owns the fix.

Tool 2 · Move 3 and Move 4

The Conference Hub

Projected class event

One screen that runs a whole writing conference: three papers read aloud with the authors hidden, a blind class vote on which argument is most convincing, then six named feedback groups — each with one fix to make and one line of that student's own writing held up as the thing that already works.

The problem

Peer feedback is usually either "I liked it" or a popularity contest. And twenty writers need twenty different fixes.

What I built

Names hidden until after the vote, so the room judges the argument. Then every student lands in a group named for the one move they are working on.

The design rule

Nobody gets a next step without first being shown a sentence of their own that works. Growth framing is structural, not a tone I remember to use.

What this sample shows

Why I build these myself

Instructional design

Reference material structured the way a stuck ten-year-old actually enters it: one page, one move, one first instruction.

Assessment design

A blind vote separates the quality of an argument from the popularity of its author, and gives the class a reason to listen closely.

Differentiation that scales

Six groups, each named for a skill, built from what the drafts actually showed. Every student gets a specific next step the same afternoon.

I ship the tools

Self-contained HTML, no logins or student accounts, works offline on whatever device is in the room, prints cleanly for families.

Student data discipline

Live tools hold real names and never leave the class. Everything I share publicly — including this page — carries a fictional roster and invented sample writing.

A system, not one-offs

Shared branding, shared print rules, a documented build and provenance protocol, so the next tool is consistent with the last one.
